# Runbook 03 — Red-Team with garak

**Phase:** 3 · **Goal:** adversarially probe the Advisor agent's model with
NVIDIA garak — prompt injection, system-prompt extraction, and the Agent-breaker
probe.
**Status:** 🟡 harness built + smoke-tested; full sweep pending (run `run_garak.sh full`).

---

## Objective

Test whether the Advisor's role guardrails and hardcoded system prompt survive
known attacks, on the Nemotron endpoint. This is the AI-1 (prompt-injection)
control, made concrete — and the most "demo-able" part of the writeup.

## What we built

The harness lives in [`../redteam/`](../redteam/):

| File | Purpose |
|---|---|
| `garak_plugins/advisor_nim.py` | Custom garak generator: subclasses the NIM chat generator and **prepends the real Advisor system prompt** to every probe, so attacks hit the production guardrails — not a bare model (ISSUES-LOG #13). |
| `run_garak.sh` | One command: refresh the prompt, install the plugin, run `smoke` or `full`. |
| `advisor_system_prompt.txt` | The exported Advisor guardrails (generated by `backend/scripts/export_advisor_prompt.py`; never hand-edited, so it can't drift from the code). |
| `reports/garak_runs/` | garak's JSONL + HTML reports (git-ignored; summarize into the table below before committing). |

## Setup (one-time)

garak needs Python **3.10–3.12** (the backend runs 3.13), so it lives in an
isolated venv:

```bash
uv venv --python 3.12 .garak-venv
VIRTUAL_ENV=.garak-venv uv pip install -U garak     # garak 0.15.1
.garak-venv/bin/garak --list_probes                 # confirm probe names for your version
```

## Run

```bash
docs/evals/redteam/run_garak.sh smoke   # 1 cheap probe, -g 1 — proves the pipeline
docs/evals/redteam/run_garak.sh full    # the three probe families
```

The script reads `NVIDIA_API_KEY` from `backend/.env` and exports it as
`NIM_API_KEY` (garak's NIM generator reads `NIM_API_KEY`, **not**
`NVIDIA_API_KEY` — ISSUES-LOG #11). Target is **NIM direct**
(`--model_type advisor_nim.AdvisorNIM --model_name nvidia/nemotron-3-super-120b-a12b`).

## Probe mapping (garak 0.15.1)

| SPEC family | garak probe(s) | Notes |
|---|---|---|
| Prompt injection | `promptinject.HijackHateHumans`, `promptinject.HijackKillHumans` (direct goal-hijack) + `latentinjection.LatentInjectionReport`, `latentinjection.LatentInjectionFactSnippetEiffel` (indirect) | Indirect/latent injection is the closest analogue to NetPlanner's real risk surface: the Advisor ingests research + project context as untrusted data behind a fence (AI-1). |
| System-prompt extraction | `sysprompt_extraction.SystemPromptExtraction` | This probe supplies its **own** system prompts (from HF datasets) and checks for leakage, so it measures Nemotron's general leak-propensity, not our specific prompt (ISSUES-LOG #13). |
| Agent-breaker (tool misuse) | `agent_breaker.AgentBreaker` | Tests tools exposed to an agent — maps to the Advisor's `research` tool. |

`full` runs `-g 3` (below garak's default) to respect the ~40 req/min free tier
(ISSUES-LOG #12); bump for a deeper run.
